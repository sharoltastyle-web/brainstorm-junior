# MILESTONES — BrainStorm ג'וניור

תוכנית פיתוח ל־MVP על בסיס `PRD.md`, `ARCHITECTURE.md` ו־`DESIGN.md`, לאחר פישוט הארכיטקטורה (ADR-1): מפתח AI יחיד הנשמר בפיתוח ב־`backend/.env`, פיתוח ובדיקה מקומיים עד אבן הדרך האחרונה, ואז פריסה אוטומטית מ־GitHub ל־Vercel. מסמך זה הוא תוכנית לביצוע עתידי, ולא דיווח על אפליקציה שכבר פותחה.

## סדר הפיתוח והתלויות

| Milestone | שם ותוצר מרכזי | תלות |
| --- | --- | --- |
| M1 | מעטפת מעוצבת ותחילת משחק: שלושת המסכים, בחירת גיל, ניווט ו־Backend עם הפרדת סודות | קבצי התמונה בתיקיית `images/`. |
| M2 | שאלה ראשונה מקצה לקצה: AI, בחירה אחת ומשוב | השלמת M1 ואישור המשתמשת. |
| M3 | המשך משחק: החלפת נושא, מניעת חזרות ומניעת לחיצות כפולות | השלמת M2 ואישור המשתמשת. |
| M4 | התקנה כ־PWA ומעטפת Offline | השלמת M3 ואישור המשתמשת. |
| M5 | חיבור ל־Vercel, פריסת MVP ל־Production ואימות הגרסה החיה | השלמת M4, אישור המשתמשת ותנאי ההפעלה. |

M2–M4 הם Vertical Slices של יכולות משתמש, עם UI, לוגיקה, Backend ובדיקות לפי צורכי היכולת; אין חלוקה לאבני דרך נפרדות של Frontend ו־Backend.

## Development Execution Rules — הנחיות מחייבות ל־AI המפתח

1. יש לפתח את ה־Milestones לפי הסדר שהוגדר במסמך.
2. לאחר השלמת כל Milestone יש לעצור את הפיתוח ולהציג למשתמשת את התוצר שהושלם ואת תוצאות הבדיקות מול כל סעיפי ה־Definition of Done שלו.
3. **אין להתחיל בפיתוח ה־Milestone הבא ללא אישור מפורש של המשתמשת.** שתיקה או בקשת סטטוס אינן אישור.
4. דיווח ההשלמה כולל דרך ברורה לבדוק את התוצר, תוצאות הבדיקות וחסמים. אין לדווח על בדיקה שלא הורצה כאילו עברה.
5. סעיף Definition of Done שנכשל או נחסם נשאר פתוח. ניתן לתקן בתוך אותו Milestone; מעבר לשלב הבא דורש השלמה או החלטה מפורשת של המשתמשת על שינוי ההיקף.
6. אין להוסיף מסכים או פיצ'רים מעבר למקורות. שינוי דרישת מוצר מחייב הצגה למשתמשת לפני מימושו.

## כללים משותפים לכל השלבים

- הסוד היחיד שמוגדר לאפליקציה הוא `OPENAI_API_KEY`. בפיתוח הוא נמצא ב־**`backend/.env`**, שנטען ב־Backend בלבד ומוחרג ב־`.gitignore`. אין מפתח בקוד ה־Frontend, ב־bundle, בתגובות API, ב־Cache או בלוגים. ב־Git מותר `backend/.env.example` עם ערך ריק בלבד.
- M1–M4 מפותחים ונבדקים מקומית, כשה־API רץ דרך שרת הפיתוח של Vite. העבודה נעשית על `main`. לפני כל Push מריצים type-check, lint, בדיקות Vitest ו־Build. Vercel מחובר רק ב־M5; מאותו רגע Push ל־`main` מפרסם ל־Production.
- **אין Database, Redis, חשבונות או Database Migrations.** המשחק ורשימת השאלות שהוצגו נמצאים בזיכרון הדפדפן בלבד.
- התשובה הנכונה וההסבר מגיעים לדפדפן עם השאלה ואינם מוצגים לפני המענה. ניסיון יחיד ומניעת חזרות נאכפים בממשק; אין טענה לאכיפה בשרת.
- ZDR מאושר הוא תנאי לשימוש בנתוני ילדים לפי ה־Architecture. עד לאימותו משתמשים בתוכן סינתטי של מבוגרים בלבד ונתיב הילדים חסום. Fixtures לבדיקות אינם מאגר שאלות של המוצר ואינם הוכחה לחיבור AI חי.
- בכל שלב נשמרים שלושת המסכים בלבד, עברית ו־RTL, ללא ניקוד מצטבר, טיימר, הרשמה או היסטוריה בין ביקורים. העיצוב נבדק מול DESIGN.md והתמונות.

## M1 — מעטפת מעוצבת ותחילת משחק ✅

### שם ומטרה

להקים בסיס עובד במחשב שבו המשתמשת נכנסת לאפליקציה, קוראת אודות, בוחרת קבוצת גיל ומגיעה למסך הטריוויה, עם הפרדה תקינה בין Frontend, Backend וסודות.

### מה יש לממש

- React/TypeScript, Vite, CSS Modules ותיקיית `backend` לפי ה־Architecture, עם lockfile ופקודות type-check, lint, test ו־build.
- `/api` עם adapter ל־Vercel Function, ו־middleware בשרת הפיתוח של Vite המפעיל את אותו handler מקומית. בשלב זה ה־handler מחזיר תשובת "לא זמין עדיין"; יצירת השאלה תושלם ב־M2.
- טעינת `backend/.env` בשרת בלבד, `backend/.env.example` ריק ואימות ש־`.gitignore` מחריג את הקובץ האמיתי.
- בית ואודות לפי ה־Design: לוגו, איורים, טקסט, צבעים, פונטים וניווט תחתון, עם התמונות מתיקיית `images/`. מסך הטריוויה כולל בשלב זה את אזור הנושא.
- בחירה יחידה בין 6–8 ל־9–12, התחלת משחק ושמירת הגיל בזיכרון מעל המסכים. אין התחלת משחק ללא בחירה ואין שחזור לאחר רענון.
- הדרכת המשתמשת לפתוח בירור ZDR מול OpenAI במקביל לפיתוח; אין להציג אישור שטרם התקבל כקיים.

### תוצר מצופה

אפליקציה מעוצבת שרצה במחשב עם שלושת המסכים. אפשר לבחור גיל, לעבור לטריוויה ולקרוא אודות; ה־Backend טוען את הסוד בצד השרת בלבד. יצירת שאלה עדיין אינה יכולת שהושלמה.

### Definition of Done

- [ ] בחירת כל קבוצת גיל מובילה לטריוויה עם הגיל הנכון; ללא בחירה לא מתחילים. מעבר לאודות וחזרה שומר מצב, ורענון מאפס אותו.
- [ ] בית ואודות תואמים למבנה ולשפה העיצובית, כולל התמונות, הניווט RTL פועל ואין מסך נוסף או רכיב הרשמה.
- [ ] `git check-ignore` מוכיח ש־`backend/.env` מוחרג; `git ls-files` מוכיח שאינו tracked. קובץ הדוגמה מכיל ערך ריק בלבד.
- [ ] בדיקה בשרת מאשרת טעינת המשתנה בלי להדפיסו; בדיקת bundle מאשרת שאינו מגיע ללקוח. משתנה VITE_ אינו מכיל סוד. מפתח חסר מטופל בשרת בלי לחשוף ערך.
- [ ] type-check, lint, בדיקות ו־Build עוברים מקומית.

## M2 — שאלה ראשונה, תשובה אחת ומשוב ✅

### שם ומטרה

לממש מסלול שלם מבחירת גיל ונושא ועד לשאלה שנוצרה ב־AI, בחירת תשובה אחת וקבלת משוב והסבר.

### מה יש לממש

- `POST /api/v1/questions` עם Zod וחיבור לממשק הטריוויה. בתחילת השלב מוודאים שהמודל שנקבע ב־Architecture זמין.
- Pipeline לפי ה־Architecture: אימות נושא, Moderation לקלט, קריאת יצירה אחת לפי גיל עם Structured Outputs, אימות מבנה, Moderation לפלט, ניסיון חלופי אחד לכל היותר וערבוב האפשרויות.
- הצגת ארבע תשובות בלי להציג את הפתרון, נעילת הבחירה הראשונה ובדיקתה בדפדפן. משוב הצלחה/טעות והסבר קצר באותו מסך; בטעות מוצגת התשובה הנכונה.
- מצבי טעינה וכשל ונוסחים בעברית: נושא ריק, לא מובן, לא מתאים, refusal, פלט חסר, timeout ומיצוי תקציב. אין הצגת תוכן חלקי.
- בדיקת Origin ו־Content-Type, גבולות קלט ו־output tokens, timeouts ולוגים ללא תוכן או סודות.

### תוצר מצופה

במחשב אפשר לקבל שאלה משירות AI אמיתי, עם תוכן סינתטי, לבחור תשובה פעם אחת ולראות משוב והסבר. רצף שאלות והחלפת נושא יושלמו ב־M3.

### Definition of Done

- [ ] מסלול חי של גיל, נושא, יצירת שאלה ומענה עובד בשתי קבוצות הגיל; ההדגמה אינה מסתמכת על Fixtures בלבד.
- [ ] בדיקות עם Fixtures מוכיחות שתוצר חסר, ארבע תשובות שאינן שונות או תוכן שנפסל אינם מוצגים. refusal ו־timeout מסתיימים בהודעה ולא בטעינה אינסופית.
- [ ] נבדקו מענה נכון ושגוי: בשניהם הסבר מותאם לגיל ובטעות פתרון מפורש. לאחר הקליק הראשון אי אפשר לבחור תשובה אחרת. הפתרון וההסבר אינם מוצגים במסך לפני המענה.
- [ ] בדיקת Network ו־bundle מאשרת שמפתח ה־AI אינו מגיע לדפדפן.
- [ ] בדיקות Vitest ו־Build עוברים; דוגמאות עברית לשני הגילים נסקרו בידי מבוגר. ללא אישור ZDR ההדגמה סינתטית ונתיב הילדים חסום.

## M3 — המשך משחק ומניעת חזרות ✅

### שם ומטרה

לאפשר משחק חוזר באותו ביקור: עוד שאלות, החלפת נושא וחזרה אליו, ללא שאלות חוזרות וללא בלבול מלחיצות כפולות.

### מה יש לממש

- „עוד שאלה באותו נושא” והחלפת נושא דרך השדה הקיים, עם שמירת קבוצת הגיל ורשימת Seen לאורך המשחק.
- שליחת עד 20 שאלות אחרונות בנושא למודל, השוואת טקסט מנורמל בשרת ובדפדפן מול כל רשימת Seen, וניסיון חלופי אחד לכל היותר לבקשה.
- בקשת יצירה פעילה אחת, לחצן מושבת בזמן טעינה, requestId מקומי והתעלמות מתגובה ישנה.
- שינוי גיל בבית מבטל את השאלה הפעילה אך אינו מוחק Seen; מעבר לאודות וחזרה שומר את המשחק.
- הודעת חיבור כשמבקשים שאלה ללא אינטרנט; שאלה שכבר מוצגת ניתנת למענה גם ללא חיבור.

### תוצר מצופה

משחק מתמשך במחשב שבו אפשר להמשיך, לשנות נושא ולחזור אליו, כל עוד הדף פתוח.

### Definition of Done

- [ ] נבדק רצף שאלות, מעבר נושא וחזרה לראשון. מועמד כפול שנכפה בבדיקה נפסל לפני תצוגה, כולל הבדלי פיסוק ורווחים. רשימת Seen אינה מוגבלת ל־20 השאלות שנשלחות למודל.
- [ ] כשאין שאלה תקינה וחדשה לאחר הניסיון החלופי, מוצגת הודעה מתאימה ואפשר לנסות שוב או לשנות נושא. אין לולאת AI בלתי מוגבלת.
- [ ] לחיצות כפולות אינן יוצרות בקשות מקבילות; תגובה ישנה אחרי החלפת גיל או נושא אינה דורסת את המצב הנוכחי.
- [ ] ניתוק לאחר קבלת שאלה עדיין מאפשר מענה ומשוב; בקשת שאלה חדשה ללא חיבור מציגה הודעת חיבור.
- [ ] שינוי גיל, ניווט לאודות וחזרה ורענון מתנהגים לפי המקורות; אין אחסון משחק ב־localStorage, sessionStorage, IndexedDB או Cookie.
- [ ] בדיקות Vitest לתרחישים לעיל ובדיקות M2 עוברות.

## M4 — PWA ומעטפת Offline ✅

### שם ומטרה

להכין את האפליקציה להתקנה ולפתיחת המעטפת ללא רשת, תוך שמירת ההבחנה בין מעטפת Offline לבין יצירת שאלות המחייבת חיבור.

### מה יש לממש

- Manifest בעברית ו־RTL, אייקונים הנגזרים מ־`images/app-icon.png`, standalone ו־Service Worker באמצעות Workbox.
- Precache של שלושת המסכים, פונטים, איורים ואייקונים; API מסוג NetworkOnly ומוחרג מ־fallback.
- אין Cache של שאלות, תשובות או בקשות, ואין Offline queue, Push או Background Sync.
- עדכון Service Worker ללא reload כפוי בזמן משחק.
- בדיקות מובייל מול ה־Design: טיפוגרפיה, מגע, Focus, גלילה בתוכן ארוך, RTL וניווט שאינו מסתיר תוכן.

### תוצר מצופה

Build שרץ מקומית (`vite preview`) עם Service Worker פעיל: לאחר טעינה ראשונה אפשר לפתוח את המעטפת ללא רשת. התקנה בטלפון אמיתי נבדקת ב־M5, כשיש כתובת HTTPS.

### Definition of Done

- [ ] ב־Build המקומי ה־Manifest וה־Service Worker נטענים ללא שגיאות, והדפדפן מזהה את האתר כניתן להתקנה.
- [ ] אחרי טעינה ראשונה נותקה הרשת: המעטפת והנכסים זמינים, ומוצגת הודעת חיבור במקום יצירת שאלה.
- [ ] Cache Storage אינו מכיל מפתח, נושאים, שאלות או תשובות. בקשת API אינה מקבלת HTML של מעטפת.
- [ ] נבדק עדכון מ־Build קודם ללא reload כפוי בזמן שאלה.
- [ ] שלושת המסכים נבדקו ברוחבי מובייל ובתוכן ארוך: אין טקסט חתוך או כפתור מוסתר; טווחי הגיל ו־BrainStorm בכיווניות הנכונה והניווט RTL עקבי.
- [ ] בדיקות M2–M3 ו־Build עוברים. Vite dev בלבד אינו ראיה להשלמת השלב.

## M5 — חיבור ל־Vercel ופריסת Production ✅

### שם ומטרה

להעמיד MVP חי על Vercel עם קוד ב־GitHub, סוד בצד השרת בלבד, תקרת הוצאה ותנאי שירות מאומתים להפעלה המיועדת.

### מה יש לממש

- הדרכת המשתמשת צעד אחר צעד בחיבור ה־Repository ב־GitHub ל־Vercel ובהגדרת OPENAI_API_KEY כמשתנה סביבה של Production, בלי לשלוח את המפתח בצ'אט.
- הדרכת המשתמשת בהקמת פרויקט OpenAI ייעודי עם תקרת הוצאה חודשית, ובבדיקה שהתקרה חוסמת ולא רק מתריעה.
- אימות ZDR למודל ול־endpoints, store:false והגבלות caching/retention. הפעלת נתיב ילדים רק לאחר אימות בפועל.
- בדיקת HTTPS, headers, rewrites ו־timeouts. Push ל־`main` לאחר אישור, פריסה אוטומטית ו־Smoke tests בכתובת החיה.
- בדיקת התקנה כ־PWA בטלפון אמיתי.

### תוצר מצופה

כתובת Production שבה פועלים שלושת המסכים, שאלה ומענה, המשך משחק ו־PWA. אם הסדר ZDR חסר, ניתן להציג גרסה לבדיקה עם תוכן סינתטי, אך שלב זה אינו מושלם כמוצר המוכן לשימוש ילדים.

### Definition of Done

- [ ] הוצגו למשתמשת הגרסה ותוצאות הבדיקות המקומיות והתקבל אישור מפורש לפריסה. אין פירוש לאישור Milestone קודם כאישור אוטומטי לפריסה.
- [ ] תנאי ZDR אומתו בחשבון בפועל; דגל קוד אינו תחליף לאישור. אין בדיקות עם נתוני ילדים לפני עמידה בתנאי. — **לא רלוונטי:** פרויקט לימודי שאינו מפורסם ואינו משותף עם ילדים (החלטת המשתמשת, ADR-6).
- [ ] ב־Production מוגדר רק OPENAI_API_KEY, בשרת בלבד. בדיקות Git, bundle, API ו־Cache מאשרות שהמפתח וקובץ .env אינם נחשפים.
